# Cooperative operation permits

Design 45 first establishes ordinary-operation cooperation, then adds the separately authenticated human Control interface in version 0.23.0. The native owner-only acceptance gate remains separate from automated fake-process evidence; agents never acquire a real human lease or answer a native dialog.

`permits.py` owns pure endpoint candidates, checked stable lock storage and process/thread-bound producer permits. `coordination.py` plans complete semantic operations and passes a bound native client through nested helpers. `herdr.py` independently asserts resources for each participating mutation and passes only relevant lock descriptors to that exact native child. A descriptor preserves exclusion after parent death; it does not grant terminal input authority. Normal release closes descriptors without explicit unlock, so a surviving child retains its open-file description's locks.

Resources are separate workspace (`W`), name (`N`), pane (`P`) and terminal (`T`) keys. Acquisition is nonblocking and ordered by endpoint, then W/N/P/T and identifier. Ordinary producers use shared resources, with exclusive W for geometry changes. Workspace creation acquires its newly returned W before returning a target; an operation holding exclusive W derives fresh P/T only from its native creation/move response. Other nested expansion is refused. Independent exclusive-holder fixtures test contention; the production human-permit factory is internal to the authenticated lease worker and has no CLI or browser resource/descriptor override.

The fake server derives expected resources independently from its world before each mutation. The common safety oracle checks those resources and live permit descriptors in addition to all existing state, key, presence, caller and ownership restrictions. Transport-unit fixtures acquire real isolated producer locks rather than exempting their calls.

Coordination holds have a typed delivery outcome distinct from input typing or blocked-state refusal. An accepted `send --now` remains the original NEW message on Held or Unavailable, including routed sends; it gains no refused/dropped receipt. Later ordinary delivery requires idle or done even when the original attempt used `--now`. The watcher rechecks the gate without reading the held terminal's prompt. Ordinary blocked/typing `--now` refusal remains unchanged.

Selected inbox reads resolve scoped headers, reject malformed/unknown/ambiguous references and invalid headers, and return already-CUR diagnostics before any coordination or mailbox lock. Valid NEW selection then acquires N, revalidates under the mailbox lock, reads/settles only that message and retains the same N through actual stdout flush. The process tests cover both the selected-read and hook flush boundaries. Held valid selections never load the body.

Default file-only consumers cover both release/debug endpoint candidates because they cannot determine the selected native binary's build flavor without a lookup. This can conservatively hold the same name in another profile. Native producers use the selected binary's bounded, top-level server-status shape to select and freeze an endpoint; flat `not_running` status still identifies an ordinary producer's endpoint. Socket/client spelling must remain consistent after canonicalization. No config directory is created by resolution.

The fixed UID lock root is outside fleet repositories. Private directories and regular, private, single-link files are validated without following symlinks. Stable inodes are never unlinked, replaced or garbage-collected automatically. They accumulate with endpoint and target churn. Descriptor budgets include prospective creation identifiers, open descriptors and cleanup headroom; allocation failure closes the whole acquisition before effects. The original semantic permit charges every derived identifier/workspace against one finite growth reservation and a cumulative 512-descriptor cap. A refused derivation preserves existing coverage and opens no more lock files. Only manual offline cleanup with no participating processes is safe.

Native execution uses a closed command-shape classifier: supported exact reads/discovery, explicit notification effects and covered mutations. Unknown, malformed and indirect dispatch commands are rejected before the runner, even when a permit is present. API-only endpoint eligibility is distinct from client-protocol eligibility: a mismatched legacy client path does not disable API delivery, but the original mismatch remains recorded and makes Watch unavailable. The observe seam converts that refusal to a typed native error; direct streams and authenticated HTTP return the normal bounded error frame, spawn nothing and release their observer slot. A user-requested preliminary lifecycle wait holds no permit; final revalidation and all effects/completion waits use the semantic permit.

The gate is not an upstream cancellation barrier. A native timeout or child exit may leave already accepted work completing later. Tests use synthetic processes to distinguish descriptor exclusion from accepted upstream work, and never treat a finite delay as a drain proof. Old/native/third-party writers remain outside cooperation. New watcher launches record `control_gate_protocol: 1`; that is participation metadata, not activation of Control or proof that an installed build is the running watcher.

Control additionally requires valid launch/build metadata and matching positive PID-generation evidence. A bounded read-only OS process fingerprint is recorded in the existing watcher lock. Disabled and positively absent/stopped watchers are distinct from unreadable, malformed, dangling, old or ambiguous evidence. Missing compatibility refuses Control; it does not pause ordinary monitoring or replace the watcher. This is cooperative launch evidence, not protection against arbitrary same-user tools forging metadata.

The human permit is opaque and creator-process/Thread scoped. It cannot authorize automated native operations, and inherited descriptors grant exclusion without input authority. The stream owner is allocated before native spawn; every normal post-spawn pipe-setup failure remains owned until exact teardown. Shared producer semantics and their central native command classifier remain unchanged.

Each lease has one writer worker, one output reader and an independent expiry signal. At most eight bounded read-only probes may be in flight service-wide; a slow probe cannot borrow input authority or trap release. Four leases, including incomplete teardown, bound controllers. Prepare nonces are capped at 64, used attempts/retired metadata at 1024; no unknown or evicted nonce authorizes acquisition. Native writes have a 500 ms budget with nonblocking stdin and independent stop/deadline checks. Output frames are bounded to 256 KiB, queued output to 32 frames/1 MiB, and one input/resize job may be in flight. Browser buffering is bounded to 32 jobs/64 KiB plus its one request; every individual text payload includes paste wrappers in its 8 KiB bound. Overflow and uncertain writes stop the lease rather than silently losing and continuing input.

The native adapter follows the pinned [terminal-session protocol](https://github.com/herdrdev/herdr/blob/2ecf19a92fc3a7fff75b6ce3655ef04f4625ec01/src/client/terminal_sessions.rs): fixed Control argv, JSON `terminal.input` text or bounded `terminal.resize`, no takeover, raw NDJSON, mouse/scroll or arbitrary command surface. Passive Watch keeps closed stdin. EOF initiates detach; bounded exact-child terminate/kill/reap and reader shutdown precede parent permit close. Incomplete cleanup retains capacity and exclusion and never emits a completed Release status. Already accepted native input or the explicitly approved restored-agent resume may still complete later; teardown is not rollback.

Watch and Control share one renderer without sharing native stream authority. At most one vendor parse is outstanding, with a validated payload of at most 196,608 bytes and application waiting work capped at 32 frames/1 MiB. The renderer awaits xterm's public write callback before any reset or new-generation frame. Reset does not cancel a queued vendor write. Invalidation immediately fences the surface, disables Copy and removes the old buffer from accessible presentation while the outstanding callback drains. A two-second parse deadline ends the affected stream and leaves input disabled; a late callback cannot restore stale authority. Native Release is signalled independently of that drain. Hidden-page behavior preserves a healthy passive Watch when Control is idle, and cancels a pending attempt without invalidating a Watch generation it never owned.

Expansion is temporary presentation, retaining the same selection, render owner and active lease. A focused viewport replaces the old normal-height minimum clamp and hides surrounding controls from layout and keyboard/accessibility order. Its same authority nodes return from the normal fixed bar to the focused sizing flow, so Release cannot occlude terminal content. Restore returns those nodes, the unchanged chosen height and saved reading position. The existing passive Watch viewport policy and explicit trusted Control layout-resize path remain separate; frame parsing and observer fitting gain no resize authority.

Expanded status feedback remains rendered, including all-or-nothing oversized-paste rejection. Normal instruction text is compacted without hiding errors. A shared fixed-bar clearance reserves normal layout and scroll/focus space, preventing native button activation from landing beneath that bar; it gives no input or resize authority.

`test_control45_dashboards.py` runs two independent authenticated dashboard OS processes with a shared isolated native endpoint, distinct fleet roots and injected controllers. It verifies cross-instance contention, routed enqueue retention after killing the owning service parent, surviving child exclusion, and one ordinary delivery after that exact child exits. Process tests separately exercise partial/complete write uncertainty, blocked pipes, output overflow, actual watcher process fingerprints and finite cleanup. These are synthetic native processes and do not establish real Herdr adapter acceptance.

The owner must perform the final real scratch Control/resize/Release acceptance after automated review and browser gates. Fake subprocesses and logical trusted-event fixtures do not establish native adapter acceptance, physical keyboard/IME behavior or an owner's dialog-answer flow. Record unavailable browser automation and simulated mechanisms honestly; do not relax trust filters to make a driver pass. Publication remains a separate owner decision.

Routed enqueue takes at most five seconds to acquire its entire root/mailbox set. It creates only validated empty mailbox infrastructure before acquisition, reserves no id and writes no message/log until the full set is held and revalidated. Typed acquisition contention alone permits retry; no automation permit survives a backoff. Permission/configuration failures and failures after a destination write are not acquisition retries. Authoritative partial success retains the original destination file with the existing receipt-recovery semantics and no source pending fallback. The watcher's noncreating `try_locked` expiry sweep is unchanged.
