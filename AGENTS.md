# herdr-fleet

A herdr plugin that starts and manages a team of named coding agents from a per-repository fleet file. Read `docs/design.md` first: it is the spec, and behaviour changes start there. `docs/requirements.md` holds the problem and the facts about herdr 0.9.4; `docs/survey.md` the prior art.

- Check herdr syntax against the installed binary (`herdr <group> --help`, `herdr --skill`) and https://herdr.dev/docs/plugins/.
- Never send keys or prompts to a herdr pane in state `blocked`, never answer another agent's permission prompt, and never run bare `herdr`.
- Don't push to a remote without the owner's explicit approval.

## Architecture

`bin/herdr-fleet` puts the plugin root on `sys.path` and calls `herdr_fleet.cli.main`, which parses arguments, runs the common preconditions (`context.preflight`) and dispatches to an operation in `ops.py` (up, restart, swap, kickoff, down, go, ui, install-cli), `checks.py` (status, drift, doctor) or `menu.py` (the `manage` and `go` popups). Operations work on a `context.Ctx` holding the herdr client, the parsed fleet file (`fleetfile.py`), the state file (`state.py`) and the plugin config, and return a `Report` that the CLI prints and maps to exit codes 0/1/2/3. `bringup.py` finds or creates the workspace, classifies each seat (live, adopted, recorded pane, or needs a pane) and starts it; `placement.py` splits the panes seats need, in chain or grid mode (design section 14), using the pure plan in `layout.py`; `tile.py` re-tiles live seats with `pane move` only (design 15.1); `seats.py` holds every interaction with a live agent: the shell-prompt check, `start_in_pane` (with the `agent_pane_busy` retry), `safe_prompt` (the only path for text to an agent; it refuses anything not `idle` or `done`, then runs the presence guard) and `quit_agent` (through `safe_prompt`, so the guard runs before every quit command too). `presence.py` is that guard (design 21.2, invariant 19): `owner_pane` (`pane get` focused, then `workspace list`: the workspace focused and its `active_tab_id` the pane's tab), the pure `prompt_line` over `pane read PANE --lines 12` with the glyphs in `seats.PROMPT_GLYPHS` and `seats.PROMPT_PLACEHOLDERS`, and `typing`, which returns `owner typing in <pane>` (status `typing`) while the owner's text, or no prompt line, is on screen in the pane they are in; the lines are read for that alone and kept nowhere. `herdr.py` is the only module that executes herdr, and it refuses `send-keys`, `send-text`, `pane run` and bare `herdr` before spawning anything. Live herdr facts the code relies on are in `docs/design.md` section 12; in particular, pane records carry no agent `name`, so read names through `agent get` (`Herdr.pane_agent`), never from `pane get`/`pane list`. `kickoff.py` renders templates; `notify.py` wraps `herdr notification show`. `messages.py` implements `send` (only `send --now` and `deliver NAME --now` may prompt a `working` agent, still through `seats.safe_prompt` with `seats.SEND_ALLOWED`; a plain `send`, the flush before it, `deliver` and `watch` leave a working seat's messages queued whatever their `queued_by`, design 21.1), the append-only message log `.herdr/messages.jsonl` and owed replies; `contacts.py` resolves `[[contacts]]` against `agent list` (contacts are messaged, never managed); `statenote.py` edits `## KEY` sections of the state note; `permissions.py` is the advisory Claude Code permission check in `doctor` (design section 16). `gitinfo.py` holds the read-only git helpers (every call sets `GIT_OPTIONAL_LOCKS=0`; nothing fetches, prunes or writes); `worktrees.py` implements `worktrees` and `checks.py` the `fleet file vs git` doctor check on top of it; `context_size.py` reads a Claude seat's context size from its transcript for `status --context`, keeping only usage numbers and timestamps (design section 17); `ack` and `--fyi` live in `messages.py`. `inbox.py` holds the mailboxes under `.herdr/inbox/<name>/{new,cur}` (ids, message files, batch rendering, moves, ttl; pure file work, no herdr and no log), `messages.py` adds the delivery engine every path shares (`prompt_mailbox`: expire, batch, `safe_prompt`, move to `cur/`, log `delivered`), and `mailroom.py` implements the `deliver` and `inbox` commands (design section 18). `watch.py` is the foreground watcher of design 18.6 (`.herdr/watch.lock`, one `agent wait --until idle --until done` thread per mailbox, delivery through `messages.prompt_mailbox`, and the hold of design 21.2 while the owner types in a seat's pane), and `hooks.py` writes the opt-in Claude Code hooks of 18.7 into `.claude/settings.local.json`, whose `inbox --hook` side lives in `mailroom.py` and prints nothing on any error. `watchpane.py` is the strip `up` opens to run the watcher below the seats (design section 19): a plugin pane recorded as `"watch"` in the state file, never a seat. `labels.py` names every live seat's pane after its seat or its `label` key (`pane rename`, design 22.1) at the end of up, restart, swap, kickoff, tile and status, and `down` clears the name of a seat pane it leaves at a shell; no other pane is ever renamed. `go` (`ops.op_go`, design 22.2) resolves a name as `send` does and runs `agent focus`, the one command that moves the owner's focus, from the CLI, the `manage` popup and the `go` popup (`menu --go`). `seen.py` records each seat's `state_seen` (design 20.5) for every command that reads seat states, through `state.record_seen`, which rewrites only that field under a lock on `.herdr/` that `save_state` also takes. `crossfleet.py` finds the other fleet of a live agent that is neither seat nor contact (its `cwd`, then `foreground_cwd`) and appends `send` and `delivered` entries and the message file there (design 20.8); it never creates a `.herdr/` directory in another repository. `scaffold.py` implements `init` (design section 13): pure file writing, no preflight and no herdr command except the optional notification. No third-party dependencies; `tomli` is vendored under `herdr_fleet/_vendor/` for Python < 3.11. Code must run on Python 3.8+: `from __future__ import annotations`, `typing.List`/`Optional`, no `match`, no `X | Y`.

## Build and test

There is no build step. Run the tests under both interpreters before handing work back:

```bash
/usr/bin/python3 -m unittest discover -s tests -v            # 3.9, vendored tomli
/opt/homebrew/bin/python3.12 -m unittest discover -s tests -v
/usr/bin/python3 -m compileall -q herdr_fleet bin/herdr-fleet
```

Tests use the fake herdr in `tests/fake_herdr.py`; never point them at a live herdr. `tests/support.py` checks every test's call log against the safety invariants of design section 7, so a new scenario is automatically a safety test (since 0.11.0 it also fails a `pane rename` of a pane that hosts no seat or to a name other than that seat's, and an `agent focus` not run by `go` or `menu`); only prompts issued by `send --now` and `deliver --now` may reach a `working` agent (`support.typed_ahead_allowed`), and no prompt may reach a pane the fake recorded as the owner's with text on its prompt line or no prompt line on screen (`owner_typing`; script it with `fake_herdr.focus`, `type_in` and `show_dialog`). The live smoke test in `docs/testing.md` is run by hand, by the designer or the owner, never by the test suite.
