# herdr-fleet

A herdr plugin that starts and manages a team of named coding agents from a per-repository fleet file. Read `docs/design.md` first: it is the spec, and behaviour changes start there. `docs/requirements.md` holds the problem and the facts about herdr 0.9.4; `docs/survey.md` the prior art.

- Check herdr syntax against the installed binary (`herdr <group> --help`, `herdr --skill`) and https://herdr.dev/docs/plugins/.
- Never send keys or prompts to a herdr pane in state `blocked`, never answer another agent's permission prompt, and never run bare `herdr`. The plugin itself presses keys only through `Herdr.agent_send_keys`, and only those of design 23.7 and 23.11 (one Enter on the exit confirmation its own quit provoked, `interrupt`'s keys, and one Ctrl-U after them when the interrupted prompt came back into the input); add no other key path.
- Don't push to a remote without the owner's explicit approval.

## Architecture

`bin/herdr-fleet` puts the plugin root on `sys.path` and calls `herdr_fleet.cli.main`, which parses arguments, runs the common preconditions (`context.preflight`) and dispatches to an operation in `ops.py` (up, restart, swap (with `--fallback`, design 35.3), kickoff, down, go, peek, interrupt, ui, install-cli), `handover.py` (`restart|swap NAME --handover` and the `handover` helper pane, design 32.5), `checks.py` (status, drift, doctor) or `menu.py` (the `manage` and `go` popups). Operations work on a `context.Ctx` holding the herdr client, the parsed fleet file (`fleetfile.py`), the state file (`state.py`) and the plugin config, and return a `Report` that the CLI prints and maps to exit codes 0/1/2/3. Walk-up discovery and `crossfleet.fleet_root` share `fleetfile.linked_worktree_fleet`: two pure file reads select the main checkout's fleet only under design 39.1's conditions, with one stderr note through `Ctx` (silent in `inbox --hook`); explicit paths stay as given, and `doctor` warns about stranded worktree mail. `bringup.py` finds or creates the workspace, classifies each seat (live, adopted, recorded pane, or needs a pane) and starts it; `placement.py` splits the panes seats need, in chain or grid mode (design section 14), using the pure plan in `layout.py`; `tile.py` re-tiles live seats with `pane move` only (design 15.1), anchoring on the `[layout] top` seat when one is set so its pane spans the width above the grid (design 26; `placement.place_band` builds that band on a fresh workspace and `placement.band_check` tells `up` when `tile` is needed); `seats.py` holds every interaction with a live agent: the shell-prompt check, `start_in_pane` (with the `agent_pane_busy` retry, `agent start --timeout 15000` (sent again without it when herdr rejects it as a usage error, `Herdr.agent_start`), and design 32.1's classification of a `timeout` from `agent get` and `process-info` alone: a late agent, a process of the kind still coming up (polled until 45 s after the first start), a bare shell (the command never ran, or the agent exited at once: one more `agent start` after a process-info read showing it, never a third; nothing typed, cleared or reset), or anything else; `bringup.start_seat` notifies every failed start, and queues the kickoff of a slow one), `safe_prompt` (the only path for text to an agent; it refuses anything not `idle` or `done`, then runs the presence guard) and `quit_agent` (through `safe_prompt`, so the guard runs before every quit command too; a hold for a dialog or menu is read again every 500 ms for up to 5 s, then refused naming the dialog's first line and notified, design 32.2; `ops._quit_live` holds the seat's mailbox lock around it, so no delivery lands on an exiting agent; when the agent is still there 3 s later it reads its screen through `seats.read_screen` (`agent read NAME --lines 16`, with one `--source visible` fallback only on `agent_not_idle`, design 36) and presses one Enter only on the kind's exit confirmation in `seats.EXIT_DIALOGS` with the exit line highlighted, never from the popup, design 23.7). `interrupt_agent` presses a working seat's `seats.INTERRUPT_KEYS` (or the `[interrupt]` table of the fleet file, then the plugin config), 300 ms apart, and waits for idle or done; `ops.op_interrupt` is its only caller, after the state check, the presence guard and `seats.read_screen` (the same `agent_not_idle`-only visible fallback) showing no dialog, and it alone presses `ctrl+u`, once, when the prompt line read after the interrupt holds text, only for a kind not in `seats.PROMPT_BOXED` (design 23.11 and 39.2); a boxed kind with restored text gets no Ctrl-U and keeps the manual-clear refusal; `ops.op_peek` prints `agent read` and writes nothing (for a working seat herdr refuses with `agent_not_idle`, it reads `--source visible` once and says so on stderr, as the board's `p` does in its footer, design 32.3). `presence.py` is that guard (design 21.2 as 23.11 and 32.8 amend it, invariant 19): `typing` reads the pure `prompt_line` over `pane read PANE --lines 12 --format ansi` (glyphs in `seats.PROMPT_GLYPHS` and `seats.PROMPT_PLACEHOLDERS`; for a kind in `seats.PROMPT_BOXED` (Kimi) the glyph must follow a box vertical, so its empty box passes and its idle-cache menu holds; the line is found without escapes, and for a kind in `seats.PROMPT_FAINT_PLACEHOLDER` every character drawn faint is dropped, so Claude Code's faint suggestion is an empty line; `interrupt`'s Ctrl-U check reads `agent read --format ansi` the same way) for every target pane, focused or not, and holds the text (status `typing`) while the line holds text or no prompt line is on screen; only then does `owner_pane` (`pane get` focused, then `workspace list`) choose the detail, `owner typing in <pane>` or `text in its input (<pane>); press Ctrl-U there to clear it`; the lines are read for that alone and kept nowhere. `herdr.py` is the only module that executes herdr, and it refuses `pane send-keys`, `pane send-text`, `pane run`, bare `herdr` and `agent send-keys` before spawning anything; `agent send-keys` runs only from `Herdr.agent_send_keys`, which accepts `enter`, `esc`, `ctrl+c` and `ctrl+u` alone (invariant 21); `ctrl+u` is restricted to the one post-interrupt cleanup path of 23.11. Live herdr facts the code relies on are in `docs/design.md` section 12; in particular, pane records carry no agent `name`, so read names through `agent get` (`Herdr.pane_agent`), never from `pane get`/`pane list`. `kickoff.py` renders templates; `notify.py` wraps `herdr notification show`. `messages.py` implements `send` (the inbox note first, design 23.1; the sender is `caller_record`: the pane's herdr name, else the one contact matching that agent, else a usage error, and `owner` only outside Herdr or after verifying a shell pane; unresolved/failed caller lookup inside Herdr requires explicit `--as NAME` (31.2); only `send --now` and `deliver NAME --now` may prompt a `working` agent, still through `seats.safe_prompt` with `seats.SEND_ALLOWED`; a plain `send`, the flush before it, `deliver` and `watch` leave a working seat's messages queued whatever their `queued_by`, design 21.1), the append-only message log `.herdr/messages.jsonl` and owed replies; `contacts.py` resolves `[[contacts]]` against `agent list` (contacts are messaged, never managed); `statenote.py` reads unique section bodies with `state get`, replaces them with `state set`, and retains them with `state append`; both writes read under a strict parent-directory flock through atomic replacement (40.3); `permissions.py` is the advisory Claude Code permission check in `doctor` (design section 16). `gitinfo.py` holds the read-only git helpers (every call sets `GIT_OPTIONAL_LOCKS=0`; nothing fetches, prunes or writes); `worktrees.py` implements `worktrees` and `checks.py` the `fleet file vs git` doctor check on top of it; `context_size.py` shares Claude/Codex provider resolution, session-specific lookup and bounded backward reading between `status --context` and the board (design sections 17 and 29); Claude counts input plus cache creation/read, Codex uses last-request total and optional reported window, never lifetime counts or inferred limits. Only usage/window numbers, timestamp and source leave the reader, and neither provider's source root is written; `ack` and `--fyi` live in `messages.py` (design 33.4: `ack --older-than D --reason TEXT` with no names or ids closes every debt in the log older than D, whoever owes it, and only for a caller the lookup finds to be `owner` whatever `--as` says; `checks` folds debts older than `STALE_DEBT_S`, 3 days, into one `status` line and marks them `stale` in JSON; `status` and `doctor` flag a mailbox that is no seat, contact or `owner`, 33.3). `inbox.py` holds the mailboxes under `.herdr/inbox/<name>/{new,cur}` (ids, message files, batch rendering, moves, ttl; pure file work, no herdr and no log; design 33.1: `is_due(message, now, fyi_ttl)` and `due_by` decide a message's own ttl and, for an FYI without one, the fleet's `fyi_ttl` (`Fleet.fyi_ttl`, seconds or None for `"off"`), and every caller passes the window of the fleet that holds the mailbox; `split_fyi` and `count_label` are 33.2's FYI-apart counts that status, the board and the fleet page share), `messages.py` adds the delivery engine every path shares (`prompt_mailbox`: expire, batch, `safe_prompt`, move to `cur/`, log `delivered`; `expire_due` logs `via` `ttl` or `fyi_ttl`; `drop_messages` is the one helper behind `--drop-inbox` and `inbox --drop`; `fleet_flag` adds `--fleet PATH` to a printed `herdr-fleet inbox` command only when discovery from the caller's cwd, ignoring `--fleet`, `--file` and `HERDR_FLEET_FILE`, would not find the fleet, 33.5), and `mailroom.py` implements the `deliver` and `inbox` commands (design section 18; `inbox --wait` polls the mailbox's files every second on `ctx.clock` and reads under the same mailbox lock as the watcher, 23.2, and keeps `.herdr/inbox/<name>/waiting.json` while it waits, which `status` and the board read, 32.4; `inbox --drop` moves queued messages to `cur/` undelivered, logged `dropped`, and with `--as NAME` runs the caller lookup (`mailroom.may_drop`) for every mailbox, one that is no seat or contact too: only NAME itself or `owner`, 33.3; `inbox --redeliver` sets the file's modification time (`inbox.touch`), from which, if later than `time`, an FYI's `fyi_ttl` window counts; `sweep_expired` is the watcher's expiry sweep, 33.1: every mailbox with queued files whose lock is free right now (`inbox.try_locked`, never waiting), timer mail left to `timers.cycle`, no timer lock, no herdr command, no new mailbox; it returns each expired message's reason, which the watcher's line names). Design 32.6: when up, restart or swap cannot send a kickoff (blocked at startup, or refused by `safe_prompt`), `bringup` queues it (`queued_by: kickoff`, ahead of everything, one per seat, replacing an older one); `compose_prompt` puts it first and verbatim, only where idle or done is required (`--now` leaves it), and `settle` logs its `kickoff` entry before the batch's `delivered` entries and sets `last_kickoff_at` through `state.mark_kicked_off`, a field-only write under the state lock. `timers.py` owns daily timer validation, planning, metadata-only occurrence history, crash recovery and read-only inspection (design section 30); `timer_calendar.py` provides one calendar interface for `zoneinfo` and the isolated native-TZ fallback, with a bounded date batch per active schedule. Timer locks precede mailbox locks, chosen ids persist before enqueue, and the scheduler never prompts or manages agents. Only the existing watcher delivery engine submits timer mail. `messages.unsettled` joins recovered timer sends by id even when delivery was logged first, while generic ordering stays unchanged; routed send receipts use the same deferred-log join with persisted per-root order (31.1). `build_identity.py` caches package version and best-effort local checkout commit (Git optional locks disabled); `watch.acquire` stores launch identity in the existing PID-owned lock and status compares it with the invoking CLI as current/stale/unknown (31.4). `ops.launcher_text` bootstraps only the enabled exact-id registry installation, honoring `HERDR_BIN_PATH`; lookup failures stop, hooks fail silently, and development selection is explicit (`HERDR_FLEET_BIN` or `install-cli --dev`, 31.6). `watch.py` is the foreground watcher of design 18.6 (`.herdr/watch.lock`, one `agent wait --until idle --until done` thread per mailbox, delivery through `messages.prompt_mailbox`, the hold of design 21.2 while the owner types in a seat's pane (a dialog/menu hold of any kind notifies once after `DIALOG_NOTIFY_S`, or `notify_blocked_after` when set, 39.2), and `Watcher.sweep`, at most once every `EXPIRE_SWEEP_S` (300 s) after `timers.cycle` has released its locks and outside any mailbox lock, design 33.1). On a terminal, without `--log`, it draws the board of design 24 in the strip: the waiter threads post an event to `Watcher.events` with every line they say and every wait that returns, and between passes `watch.BoardView` drains that queue, rebuilds the model after an event or every 5 s, draws, and reads keys; every line then goes to `.herdr/watch.log` and the footer instead of stdout (a `LineSink` catches what other code prints), and the delivery paths are the same as in log mode. `board.py` holds the model (`build`: FYIs counted apart in each row's `queued`/`fyi` and in the fleet page's `queued:` line, 33.2; one `agent list`, `pane get` for a working seat's title, `seats.read_screen` with `agent read --lines 16` only for a blocked seat (with design 36's one visible fallback on `agent_not_idle`) and only up to four lines of its dialog through `seats.dialog_lines`, `state_seen`, the mailboxes, `messages.owed` parsed again only when the log changed, the transcripts' context size and optional window through the shared reader, cached by provider/root/session and path/mtime/size), the pure `render(board, width, height, colours)`, lines of `(text, style)` spans, and the view stack of design 25 (`BoardPage`, the root; `SeatPage`, `FleetPage`, `OwnerPage`, `ContactPage` and `Body`, each with `load`, `render` and `key`, a key giving back an action tuple that `BoardView.act` carries out); `tui.py` is the `Screen` it draws on (`size`, `draw`, `getch`, which also returns clicks as `("click", row, col)`; `CursesScreen` imports `curses` lazily, so nothing else needs it, and `FakeScreen` records draws and replays scripted keys and clicks for the tests) and `tui.zoom`. The board's keys only call existing functions: `g` `ops.op_go`, `p` `ops.op_peek`, `a` `messages.op_ack` with `--reason "from the board"` as `owner`, `d` `Watcher.deliver` for idle or done seats, `z` `Herdr.pane_zoom_toggle` on the strip's own pane (an explicit pane id from `HERDR_PANE_ID`, else the state's watch pane; never `--current`, design 25.7); drawing and navigation prompt nothing and send no agent key; `d` uses the watcher's guarded delivery path, and `agent focus` and explicit own-pane `pane zoom` run only on a key (invariant 22). `hooks.py` writes the opt-in Claude Code hooks of 18.7 into `.claude/settings.local.json`, whose `inbox --hook` side lives in `mailroom.py` and prints nothing on any error. `watchpane.py` is the strip `up` opens to run the watcher below the seats (design section 19): a plugin pane recorded as `"watch"` in the state file, never a seat. `handover.py` (design 32.5): `request` refuses any seat but the caller's own (a usage error), opens the `handover` plugin pane in a new tab of the seat's workspace (`plugin pane open --placement tab --no-focus`, `HERDR_FLEET_HANDOVER` in its env) and records it as `"handover"`; `op_handover` runs only in that recorded pane, `agent wait`s for the seat's turn to end, then runs `ops.op_restart` or `ops.op_swap` for that one seat from its own pane, waits again when the seat turned working, stops on anything else (Enter keeps the pane until read), and on success closes its own pane. The watcher never starts or acts for it. `labels.py` names every live seat's pane after its seat or its `label` key (`pane rename`, design 22.1) at the end of up, restart, swap, kickoff, tile and status, and `down` clears the name of a seat pane it leaves at a shell; no other pane is ever renamed. `go` (`ops.op_go`, design 22.2) resolves a name as `send` does and runs `agent focus`, the one command that moves the owner's focus, from the CLI, the `manage` popup, the `go` popup (`menu --go`) and the board's `g` key. `seen.py` records each seat's `state_seen` (design 20.5) for every command that reads seat states, through `state.record_seen`, which rewrites only that field under a lock on `.herdr/` that `save_state` also takes. `crossfleet.py` owns validated destination discovery, sorted-root id reservation and paired-header receipt checks for new cross-fleet sends (design 31); the destination has the sole pending queue, while the source has nonpending history and mirrored terminal records. Local seats stay local. Legacy mirror helpers apply only to old source-owned queues; stored history is never migrated or replayed. Receipt mirroring takes no root lock while a mailbox lock is held, preserving timer-before-mailbox ordering. `scaffold.py` implements `init` (design section 13): pure file writing, no preflight and no herdr command except the optional notification. Design 35 (0.19.0, provider tiers and failover on a limit): `fleetfile.py` parses `[tiers.NAME]` and tier seats (`tier`, `prefer`, `extra_args`; `Seat.variants` holds each kind's arguments and quit, `Seat.use(kind)` makes one the effective `kind`, `args` and `quit`, so every reader sees the effective pair) and `failover_at_percent`; `Ctx.apply_failover` switches a seat whose state entry records `failover.to` whenever the fleet is loaded, and `up`, `restart` and the drift check use whatever the seat then is. `limits.py` is the pure side of limits (`limit_line` finds the provider's message in `seats.LIMIT_PATTERNS`, skipping prompt-glyph and assistant-bullet lines; `limit_block` accepts only its wrapped lines and `seats.LIMIT_TRAILERS` above an empty input for the limited quit, 37.1; `parse_reset`, `new_record`, `counts`/`holds`/`records`/`replaced`, `holding`/`release`, `fallback_candidates`); the `limited` record lives in the seat's state entry (with `limited_also` for older records of other kinds) and, like `state_seen`, is written field-only under the `.herdr/` lock (`state.patch_entry`, kept by `save_state`), as is the top-level `codex_allowance` (`state.patch_top`). `watch.Watcher.limit_cycle` follows the state file each pass (holds through `limit_holds`, shown with the hold mechanism of 21.2; resets notified once) and every `LIMIT_SCAN_S` runs `scan_limits`: each seat whose kind has limit patterns, whose state is idle, done or working and has not changed for `LIMIT_QUIET_S` is read once per (`state since`, last logged prompt) pair with `agent read NAME --lines 12` (`pane read` only on `agent_not_idle`), whatever its queue, once both ages are at least `LIMIT_QUIET_S`; `refresh_last_prompts` reads `messages.jsonl` incrementally only when its size, mtime or inode changes, resets to zero on inode replacement and keeps only each seat's newest prompt timestamp (39.3), and `limits.limit_line` counts a match only within the last 6 non-blank lines above the input area, anchored at the start of the cleaned line (design 35.6, 35.5 item 18); every `ALLOWANCE_READ_S` one Codex rollout's `rate_limits` numbers via `context_size.seat_allowance`; it notifies and holds and nothing more. `ops._swap_fallback` (several names, or every limited tier seat) is the only code that moves a seat to another kind, trying each candidate at most twice and moving past a failed start only after a fresh read finds no agent and a bare shell (37.2); when Codex is a candidate it uses a fresh state reading or `context_size.latest_allowance` (newest rollout in the newest two date dirs, bounded and numbers-only) and moves an above-threshold, unexpired Codex last without dropping or recording it, including on a dry run (39.4), while `fallback_note` and `failover.reason` quote only a counting record of the kind left (39.5), and `ops.limited_working` (with `Ctx.limited_quit` and `seats.quit_agent`'s `allow`) is invariant 11's one new exception: a seat the state marks limited, whose record is of the live agent's kind and which `state_seen` shows `working` since before the record, is quit while herdr reports it `working` after a fresh read satisfies `limits.limit_block` (37.1); `ops.op_swap` skips failed-over seats without names and returns one to its primary for `swap NAME`; `mailroom.release_limit` is how `deliver NAME` (and the board's `d` on a seat page) ends a hold, while a bare `deliver`, `watch --once` and the board's `d` leave a held seat alone (`limited_line`). `messages.last_request` reads the log for the failover note. No new key path and no new prompt path. No third-party Python runtime dependencies; `tomli` is vendored under `herdr_fleet/_vendor/` for Python < 3.11. Code must run on Python 3.8+: `from __future__ import annotations`, `typing.List`/`Optional`, no `match`, no `X | Y`.

`context.detect_invocation` records `CODEX_THREAD_ID` in CLI mode only. `context.resolve_caller` finds that thread's unique `herdr:codex` session in preflight's `agent list` and uses its pane and workspace for caller identity and own-pane guards (design 38). A missing or ambiguous thread leaves both unknown; identity commands require `--as NAME`, which sets no pane. `context.caller_panes` protects every possible caller when unresolved: every live Codex pane, including panes with a recorded different thread, since that record may be stale. Restart, swap, down and interrupt refuse them before any wait or action. Plugin actions and panes keep Herdr's invocation context; a CLI Codex watcher's zoom uses the recorded strip.

Section 40 (0.20.0): `mailroom` resolves `--show ID` and `--read ID` only inside the selected mailbox. Show is file-only with no expiry, state observation or lock creation; selected reading validates before locking, revalidates under the mailbox lock and settles or expires that message alone. Bulk read/wait is unchanged. `inbox.direct_text` supplies every ordinary direct message's actual sender/id even for a pre-prefixed body; stored bodies, timer/batch headers and queued-kickoff composition stay verbatim. `messages.expired_fyi` derives seven-day expiry metadata from the log, shared by `log --expired-fyi` and status's existing log read; new FYI expiry records retain sender/FYI metadata without changing receipt ownership. Queue reason `refusal` displays as `[plain send]`; cross-fleet alias mappings display only differing names. No new Herdr command, key, prompt or debt policy.

`dashboard.py` owns the foreground loopback HTTP server, per-launch owner capability/session, exact Host/Origin/anti-forgery checks and fixed packaged asset allowlist (design 41). `dashboard_data.py` registers canonical explicit/discovered fleets and observes them without `Ctx`, state writes, mailbox locks, expiry or pane labels; one bounded agent snapshot serves each refresh, with stale retention and bounded file caches. `dashboard_actions.py` creates request-local owner contexts only after authenticated explicit POST validation, revalidates roster/routing/seat generations and selected owner-message evidence, then uses the existing selected inbox/read and ordinary `messages.op_send` paths. Its strict directory-locked, fsynced metadata-only intent journal reserves before effects, releases before mailbox work and retains uncertain/crashed attempts without replay or pruning; an optional body-free per-target `op_send` callback records actual ids/receipt outcomes without changing ordinary CLI behavior. `dashboard_terminal.py` validates ANSI full/delta frames and owns bounded passive observers, revalidating authority and target identity until disconnect/rebinding/shutdown; `Herdr.terminal_observe` is the sole streaming execution seam, with fixed observe-only arguments and closed stdin, injectable for fake processes. Generic terminal commands and `agent attach` are forbidden. `dashboard_static/` packages the external production UI and pinned MIT xterm/fit bundles, including attribution, upstream integrity, patched asset hashes and the documented style-nonce patch. `dashboard_demo.py` supplies a separate authored synthetic run with no live registry/Herdr/action adapter. The browser exposes owner messages and read-only Watch; no input, lifecycle, focus, key or command surface is added.

## Build and test

There is no build step. Run the suite with an available Python below 3.11 and one at or above 3.11 before handing work back; substitute their absolute paths when needed:

```bash
python3.9 -m unittest discover -s tests -v    # vendored tomli
python3.12 -m unittest discover -s tests -v   # standard-library tomllib
python3 -m compileall -q herdr_fleet bin/herdr-fleet
```

Tests use the fake herdr in `tests/fake_herdr.py`; never point them at a live herdr. `tests/support.py` checks every test's call log against the safety invariants of design section 7, so a new scenario is automatically a safety test (since 0.11.0 it also fails a `pane rename` of a pane that hosts no seat or to a name other than that seat's, and an `agent focus` not run by `go` or `menu`; since 0.12.0 any `agent send-keys` but one `enter` from restart, swap or down right after an `agent read` that showed the highlighted exit confirmation, the kind's interrupt keys from `interrupt` to a seat working at its last `agent get` whose screen it read, or one `ctrl+u` from `interrupt` after an `agent read` that showed text in the input, and any from watch, menu, deliver or a dry run, and any `agent prompt` to a pane whose prompt line held text, focused or not; script it with `fake_herdr.exit_dialog_on_quit`, `show_exit_dialog`, `interrupt_results` and `restore_prompt_on_interrupt`; since 0.18.0 `inbox --drop --as NAME` may run the caller lookup, which no other `inbox --as` may; since 0.17.0 a second `agent start` to a pane in one command that does not follow a `process-info` read showing its bare shell with no successful `agent get` in between, and any third (busy answers do not count), a plugin pane from `restart` or `swap` that is not the `handover` tab of a `--handover` command, a `handover` helper prompting, starting, keying, waiting on or reading any seat but its recorded one or closing any pane but its own, and an `agent read --source visible` from anything but `peek` or the board right after a `p`; script it with `start_lost`, `start_slow`, `start_timeout`, `no_start_timeout`, `no_ansi_format`, `pane_read_errors`, `agent_not_idle`, `show_menu`, `suggest` and `suggest_on_interrupt`; since 0.13.0 an `agent focus` from `watch` that does not follow a `g` or a number key replayed by the fake screen, a `pane zoom` that does not follow a `z` or is not on the strip's own pane, one per key, and an `agent read` from `watch` of anything but a seat whose state at the command's last `agent list` was `blocked`, unless right after a `p`; drive the board with `tui.FakeScreen(keys, on_key=self.log_key)`, `watch.is_terminal` and `tui.open_screen` patched, as `tests/test_section24.py` and `tests/test_section25.py` do); since 0.19.0 an `agent read` from `watch` is also allowed for a seat idle, done or working at the last `agent list`, with `--lines 12` and no `--source` (`limit_read_allowed`), and a quit prompt from restart, swap or down may reach a `working` seat only after a read of its pane that showed a limit line and an empty input (script it with `fake_herdr.show_limit`); since 0.19.1 an `agent read --source visible` from restart, swap, down, interrupt or the watcher is also allowed only immediately after the same target and line count's plain read answered `agent_not_idle` (script it with `fake_herdr.viewport_rows`); since 0.19.2 `swap --fallback` alone counts starts per `(pane, kind)`, at most two for each, with a bare-shell `process-info` read before the next kind's first start too; only prompts issued by `send --now` and `deliver --now` may reach a `working` agent (`support.typed_ahead_allowed`), and no prompt may reach a pane the fake recorded as the owner's with text on its prompt line or no prompt line on screen (`owner_typing`; script it with `fake_herdr.focus`, `type_in` and `show_dialog`; since 0.19.4 the fake draws Kimi's boxed input, typed text in it and its idle-cache menu, and the oracle requires the box). For manual validation, follow the current scratch-fleet workflow in `docs/testing.md`; historical release evidence lives in `docs/design.md`. Live smoke tests are run by the designer or owner, never by the test suite. For starter examples or contact-capacity changes, follow design section 27 and `tests/test_section27.py`: seats and contacts share board capacity and every hidden row counts in `+N more`.

## Public examples and publication

For example, fixture or documentation changes, use the synthetic `examples/team` identifiers and paths.
